# Восстановление истории по паролю — проектирование

Цель: обычный пользователь после переустановки вводит только логин и пароль,
а устройство восстанавливает ключи старой зашифрованной истории. Отдельный
ключ остаётся необязательной страховкой. Эта функция **ещё не включена**.

## Текущее поведение

Пароль отправляется по HTTPS шлюзу и Synapse для аутентификации. Ключи
сообщений создаёт Matrix SDK. Локальное хранилище защищено Android Keystore;
после удаления приложения оно утрачивается. Восстановление ключей выполняется
штатным механизмом SDK с пользовательским ключом или доверенным устройством.

Нельзя просто зашифровать копию ключей тем же паролем, который получает VPS:
это позволит серверу расшифровать её и нарушит выбранную модель E2EE.

## Требования к изменению

- Отделить проверку входа от секрета расшифровки копии. Рассмотреть проверенную
  реализацию PAKE/OPAQUE и интеграцию с сервером; не писать собственный PAKE.
  Перед выбором проверить поддержку Android ABI, жизненный цикл библиотеки,
  лицензирование, аудит, тестовые векторы и восстановление после сбоев.
- Копия ключей шифруется только на устройстве. Сам ключ, секрет расшифровки
  и пароль, пригодный для его получения, не должны попадать на VPS.
- Предусмотреть защиту от подмены параметров KDF, понижения версии протокола,
  повторной выдачи старой копии и перебора слабых паролей. Отдельно описать
  границы защиты при краже базы сервера.
- Сохранить существующие аккаунты, доверие устройств и историю. Миграция
  должна иметь возможность продолжиться после разрыва сети и перезапуска;
  не сбрасывать cross-signing и не перезаписывать существующий backup.
- Проверять завершение загрузки ключей, различать отсутствие копии, неверный
  пароль и недоступность сети. Не показывать успешную настройку до проверки
  восстановления на независимом клиенте.
- Обычная смена пароля при доступных ключах перепаковывает копию. Сброс по
  почте сам по себе не восстанавливает забытый секрет старой истории: нужен
  доступный доверенный клиент либо добровольно сохранённый recovery key.

## Приёмка

Реальные два Android-клиента и сервер: регистрация → обмен текстом и медиа →
создание копии → уничтожение локального состояния → вход на новом устройстве →
чтение старых сообщений и новые отправки. Затем проверить смену/забытый пароль,
миграцию старого аккаунта, неверный пароль, модификацию копии сервером, сбои на
каждом шаге, параллельный вход и отсутствие ключей/пароля в логах и бэкапах VPS.

До выполнения этих проверок интерфейс не обещает восстановление истории только
по логину и паролю.
