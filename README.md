# Личный чат

Android-мессенджер для своего VPS: Kotlin, Jetpack Compose Material 3 Expressive, Matrix Rust SDK, Synapse и Docker Compose. Регистрация открытая; приватный логин отделён от публичного `@username`.

**Статус: разрабатываемая alpha.** Нативный клиент компилируется, сервер проходит интеграционные проверки регистрации. Сквозная проверка Android → сервер → Android ещё отлаживается. Это пока не готовый защищённый релиз; не используйте для чувствительной переписки до успешной проверки и независимого аудита.

## Что реализовано

- Регистрация без приглашений: логин, username, пароль; вход по логину и паролю.
- Поиск пользователя по точному публичному username и личные зашифрованные комнаты.
- Текст, выбор фото/видео из галереи, голосовые до 3 минут и видеокружочки до 60 секунд. Файл — максимум 50 МБ.
- Расшифровка и просмотр вложений на устройстве; воспроизведение аудио/видео.
- Ключ восстановления зашифрованной истории и интерфейс проверки собеседника по эмодзи/числам Matrix SAS.
- Динамические цвета Material You на Android 12+, обычная тема на Android 8–11.
- Сборка APK и проверки в GitHub Actions.

Пока нет push-уведомлений и гарантированной доставки в фоне при закрытом приложении, звонков, группового интерфейса, удаления аккаунта, смены username, восстановления пароля по почте и защиты регистрации CAPTCHA. Обновления приходят при работающем приложении и подключённой синхронизации. Нет федерации с другими серверами Matrix. Запись/воспроизведение на разных физических устройствах ещё требуют ручной проверки.

## Регистрация

| Поле | Назначение | Ограничения |
|---|---|---|
| Логин | Вход; не возвращается поиском пользователей | 3–64 символа: `a-z`, цифры, `_`, `-`, `.` |
| Username | Публичное имя для поиска, например `@kim` | 3–32 символа: `a-z`, цифры, `_` |
| Пароль | Проверяется Synapse; приложение его не сохраняет | От 12 символов, максимум 72 байта UTF-8 |

Логин и username приводятся к нижнему регистру. Они уникальны каждый в своём пространстве. Можно выбрать разные значения. Публичный Matrix ID имеет вид `@kim:chat.example.com`. Приватность логина относится к интерфейсу и API поиска: владелец VPS имеет доступ к таблице соответствий.

## Шифрование и доверие

Криптографию сообщений выполняет официальный Matrix Rust SDK: устройства шифруют содержимое до отправки, сервер хранит зашифрованные события и байты вложений. Самописного протокола шифрования сообщений нет. Локальная база SDK зашифрована; её случайный ключ и токен сеанса защищены Android Keystore. Резервное копирование данных приложения средствами Android отключено.

VPS видит аккаунты, адреса подключений, участников комнат, время, размеры файлов и другую служебную информацию. Пароль проходит по HTTPS на сервер для аутентификации. E2EE не скрывает эти метаданные и не защищает взломанный телефон. Расшифрованные вложения и исходные записи находятся в закрытом каталоге/кеше приложения; это не защита от скомпрометированной ОС.

После первого входа создайте ключ восстановления в настройках и сохраните **вне телефона и VPS**. На новом устройстве войдите и восстановите ключи. Один пароль не восстанавливает зашифрованную историю. Не сбрасывайте криптографическую идентичность ради обхода ошибки. Для защиты от подмены ключей сверяйте эмодзи/числа с собеседником по независимому каналу; подтверждайте только совпавшие значения. Интерфейс сравнения ещё требует проверки на двух реальных устройствах.

Для совместимости с восстановлением истории используется штатная политика SDK `CrossSignedOrLegacy`: новые сессии требуют подписи устройства; импортированные резервные сессии старого формата могут расшифровываться без доказательства происхождения. У таких сообщений приложение показывает предупреждение SDK. Стандартная асимметричная копия Matrix обеспечивает конфиденциальность истории, но сервер, имеющий публичный ключ копии, потенциально может подменить её содержимое; не считайте такую историю доказательством авторства. Режим `Untrusted` не используется. Не подтверждайте подозрительные сообщения только потому, что они появились после восстановления.

Кружочек — зашифрованный MP4 с дополнительной меткой клиента; другой Matrix-клиент может показать его обычным видео.

## Быстрый запуск VPS: HTTPS на 8443

Нужны Linux VPS, Docker Engine с Compose v2, Python 3, домен с DNS-записью на VPS. Для начального тестирования можно выделить 2 ядра и 4 ГБ RAM; расход диска зависит от вложений. Порт 80 нужен Caddy для получения TLS-сертификата; порт 8443 — клиентам. При IPv6 проверьте также AAAA-запись и firewall IPv6.

```bash
git clone https://github.com/KimberlyWay/private-messenger.git
cd private-messenger
python3 server/setup.py --domain chat.example.com --url https://chat.example.com:8443
# Разрешите входящие TCP 80 и 8443 в firewall VPS/провайдера.
docker compose -f server/compose.yml --profile tls up -d --build --wait --wait-timeout 240
curl --fail https://chat.example.com:8443/healthz
```

Замените домен на свой. В Android в поле сервера укажите **`https://chat.example.com:8443`**, затем создайте аккаунт. Самоподписанные сертификаты и обычный HTTP клиент не принимает. Для порта 443 используйте URL без `:8443`; для другого порта укажите его в URL при первоначальной настройке. Генератор запишет соответствующий `HTTPS_PORT`.

`--domain` задаёт постоянную идентичность Matrix без порта. Не меняйте её после создания аккаунтов. `setup.py` откажется перезаписывать существующий `.env`: повторно запускать генератор при обновлении сервера не нужно.

### Если уже есть nginx/Caddy/Traefik

Запустите без профиля `tls`:

```bash
python3 server/setup.py --domain chat.example.com --url https://chat.example.com:9443 --port 8088
docker compose -f server/compose.yml up -d --build --wait --wait-timeout 240
```

На существующем HTTPS-прокси направьте **все пути** на `127.0.0.1:8088`, установите настоящий `X-Real-IP`, сохраните Host, разрешите тело запроса 70 МБ и тайм-аут не менее 120 секунд. Пример server-блока nginx (сертификат получаете своим обычным способом):

```nginx
server {
    listen 9443 ssl;
    server_name chat.example.com;
    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;
    client_max_body_size 70m;
    location / {
        proxy_pass http://127.0.0.1:8088;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 120s;
    }
}
```

Если прокси в другом контейнере, подключите его к сети Compose и проксируйте на `edge:8080`; localhost внутри отдельного контейнера — не хост VPS. Не публикуйте наружу PostgreSQL, gateway, Synapse 8008 или административный API. Публичный edge принимает `X-Real-IP` от доверенного внешнего прокси: внешний прокси обязан его перезаписывать.

### Обслуживание и резервная копия

```bash
docker compose -f server/compose.yml ps
docker compose -f server/compose.yml logs --tail=100 gateway synapse edge
# Остановить, сохранив данные:
docker compose -f server/compose.yml --profile tls down
```

Данные находятся в именованных Docker volumes `private-messenger_*`. **Не выполняйте `down -v` на рабочем сервере**: это удалит базы, медиа и ключ сервера. Для согласованной резервной копии остановите сервисы и сохраните все volumes, `server/.env`, `server/generated/` и конфигурацию прокси. Храните копию приватно и проверьте восстановление на отдельном хосте. Серверная копия не заменяет пользовательский ключ восстановления.

При обновлении сначала сделайте копию, проверьте release notes Synapse, затем обновляйте код/образы и запускайте Compose снова. Major-версию PostgreSQL нельзя менять простым редактированием тега образа. В репозитории закреплён Synapse 1.164.0; актуальность и исправления безопасности следует отслеживать отдельно.

Регистрация открытая для всех; шлюз ограничивает число попыток регистрации/входа по IP, но это не полноценная защита от злоупотреблений. Лимитер в памяти одного процесса; при перезапуске счётчики сбрасываются. На публичном сервере нужны мониторинг диска, ограничения ресурсов и механизм борьбы со спамом. Почтового восстановления и панели модерации пока нет.

## Android Studio и APK

1. Откройте **корень репозитория**, содержащий `settings.gradle.kts`, через Open.
2. Нужны Android Studio с поддержкой AGP 9.3.2, JDK 21 и Android SDK 37.0. Gradle скачивается wrapper-ом автоматически; в проекте Gradle 9.8.2. Используйте JDK 21 в настройках Gradle.
3. Дождитесь Gradle Sync. Подключите телефон Android 8.0+ или эмулятор и нажмите Run.
4. APK через терминал: `./gradlew assembleDebug` (Windows: `gradlew.bat assembleDebug`). Файл: `app/build/outputs/apk/debug/app-debug.apk`.
5. В GitHub откройте Actions → Android → успешный запуск → artifact `private-messenger-development-apk`.

Сейчас сборки **development/debug**. Постоянная подпись распространения ещё не настроена; не рассчитывайте на установку будущих APK поверх существующего без переустановки. Переустановка может удалить локальные ключи — сохраните ключ восстановления до неё. Ручной workflow `Signed alpha release` подготовлен: он проверяет успешность серверных, Android- и E2EE-тестов именно для выпускаемого коммита, затем собирает APK, серверный ZIP, полный исходный ZIP и SHA256SUMS. Постоянный ключ ещё не создан и не загружен; workflow не сможет выпустить APK без настройки `ANDROID_KEYSTORE_BASE64` и `ANDROID_KEYSTORE_PASSWORD` в GitHub Actions Secrets. Перед следующими версиями увеличивайте `versionCode` и `versionName` в `app/build.gradle.kts`.

Шаблон release-конфигурации читает переменные `ANDROID_KEYSTORE_PATH`, `ANDROID_KEYSTORE_PASSWORD` (alias `messenger`); приватные ключи нельзя коммитить в репозиторий.

Если Gradle не скачивается, откройте окно Build и посмотрите точный URL/ошибку. Первый запуск требует доступа к Google Maven, Maven Central и Gradle distributions; ошибки DNS, TLS, прокси и ограничения сети не исправляются удалением файлов проекта. Не включайте Offline mode до первой успешной загрузки зависимостей.

### Какие файлы можно убрать после открытия

- `.git/` — только если больше не нужны история, git и обновления через pull; Android Studio продолжит работать.
- `.github/` — если не нужны Actions и сборки на GitHub.
- `README.md`, `SECURITY.md`, `docs/` — документация, на компиляцию не влияет.
- `server/` — можно убрать из **копии Android-проекта**, если сервер уже развёрнут отдельно. На VPS не удаляйте его конфигурацию и секреты.
- `.idea/`, `.gradle/`, `.kotlin/`, `build/`, `app/build/` — генерируемые настройки/кеши; пересоздадутся. Удаление кеша вызовет повторные загрузки.
- `local.properties` — локальный путь SDK; Studio обычно пересоздаёт.

**Оставьте** `app/src/`, Gradle-файлы, `gradle.properties`, `gradle/wrapper/`, `gradlew` и `gradlew.bat`. Wrapper нужен для воспроизводимой версии сборки. Не удаляйте приватные данные действующего сервера, ключ восстановления или ключ подписи APK.

## Проверки

- `Server checks`: реальный Docker Compose; регистрация, занятые логины/username, вход, поиск только после авторизации, отсутствие приватного логина в поиске, отсутствие пароля в ошибке валидации и запрет внешнего admin API.
- `Android`: компиляция клиента/инструментального теста и Android Lint.
- `End-to-end integration`: эмулятор Android и изолированный Synapse; цель — получение текста/фото другим пользователем, проверка шифротекста на сервере и восстановление истории на новом устройстве. **Пока не проходит, отлаживается.**

Для серверной проверки локально используйте отдельную копию проекта/отдельный Docker context: CI создаёт тестовые аккаунты и удаляет volumes. Флаг `setup.py --test` разрешает HTTP только для изолированных тестов. Android-вариант `e2e` также допускает HTTP и не должен распространяться как обычный клиент.

## Структура

- `app/src/main/java/uk/mywisp/privatechat/` — Compose UI, Matrix SDK, локальный Vault, сеть входа и запись медиа.
- `server/gateway/` — регистрация и отображение приватных логинов на публичные Matrix ID.
- `server/setup.py` — первоначальная генерация конфигурации и случайных серверных секретов.
- `server/compose.yml`, `Caddyfile*` — контейнеры, внутренний HTTP и внешний TLS.
- `app/src/androidTest/` — тест реального обмена с сервером.
- `.github/workflows/` — CI.

Собственный интерфейс не является форком Element X. Зависимости сохраняют свои лицензии.
